# Naming and modelling standards

These are the team standards every pull request is reviewed against (see `.github/PULL_REQUEST_TEMPLATE.md`).

## Models

| Layer | Pattern | Example |
| --- | --- | --- |
| Staging | `stg_<market>__<dataset>` (two underscores between source and dataset) | `stg_par__deals` |
| Intermediate | `int_<entity>` ; a filtered view of one is `int_<entity>_<qualifier>` | `int_deals`, `int_deals_clean` |
| Dimension | `dim_<entity>` singular | `dim_building` |
| Fact | `fct_<entity or grain>` singular | `fct_leasing_deal`, `fct_market_quarter` |
| Mart | `mart_<audience or purpose>` | `mart_market_kpis` |
| Ops | `ops_<topic>` | `ops_dq_quarantine_summary` |
| Reference seed | `ref_<entity>` | `ref_fx_rates` |

One model, one grain, stated in the first comment line of the file. A model never reads from a
layer above its own (gold reads silver and reference; silver reads bronze, reference and silver).

## Columns

- `snake_case`, lower case, no abbreviations except the units below.
- **Units are in the name.** Areas `_m2`; rents `_eur_m2_yr` (EUR per m² per year); money `_eur`;
  rates and ratios stored as fractions are named `_rate` or `_ratio` (0.10 = 10%); percentages
  stored as percent are named `_pct` and only appear in the ops and AI layers; percentage points `_pp`.
- Anything in a market's own convention is marked: `_local` (`rent_local`, `grade_local`,
  `submarket_local_name`) with the companion `rent_currency` / `rent_unit` columns.
- Keys: `<entity>_key` for surrogate keys (md5 of the natural key, built by the `surrogate_key` macro);
  `<entity>_id` for natural or reference ids (`market_id`, `submarket_id`, `quarter_id`).
- Dates: `_date` for dates, `_at` for timestamps, `_key` for integer date keys (yyyymmdd).
- Booleans read as a question: `is_outside_tolerance`, `submarket_derived_from_building`.
- Provenance columns start with the source: `source_table`, `reported_submitted_at`, `submission_count`.

## Codes

Shared codes are short upper-case strings (`NEW`, `REN`, `FIN`, `A`) held in `ref_<entity>s` with a
name column, and every market's local labels map to them in `ref_<entity>_mapping`. Mapping is
case- and whitespace-insensitive (`normalise_text`). An unmapped label fails the build
(`tests/assert_no_unmapped_codes.sql`); it is fixed by adding a mapping row, never by special-casing
a model.

## SQL style

`sqlfluff` with the config in `.sqlfluff` is the arbiter: lower-case keywords and functions,
explicit `as` aliases, one select target per line, CTEs named for what they hold, joins on
indented `on` clauses, no `select *` out of a CTE into gold. Every CTE in an intermediate or gold
model has a one-line comment if its purpose is not obvious from its name.

## Documentation

Every model and every gold column has a `description` in the layer's `_*.yml`. Descriptions say what
the column means and in what unit, not how it is computed (that is the model's comment). KPI
definitions change only through `seeds/reference/ref_metric_definitions.csv`, and a change there is a
change to the data contract, so it is called out in the pull request.

## Governance

- `seeds/reference/` and `macros/` are owned by the analytics engineering owners (`CODEOWNERS`);
  changes need their review.
- Tolerances and thresholds are `vars` in `dbt_project.yml`, never literals in a model.
- No credentials in the repository: the Databricks target reads environment variables and uses OAuth.
- Generated files (`models/bronze/sources.yml`, `seeds/bronze/_bronze_seeds.yml`) are regenerated by
  `scripts/scaffold_market.py`, and CI fails if they are out of date.
